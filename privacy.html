Privacy Policy

Last updated: November 8, 2026

This Privacy Policy describes how Coderipple Tech Ltd ("we", "us", "our") handles information when you use the Ripple Import application ("the App") on the monday.com platform.

1. Summary

Ripple Import imports data in two ways, and they handle your data differently:

  • Uploading a file (the standard import). The file is read in your browser, and its rows go from your browser straight to your monday.com board through monday.com's API. The file and its contents never reach our servers or any third party.
  • Scheduled imports from a link (optional, off until someone on your account sets one up). Our backend, hosted on monday.com's own app platform (monday code), downloads the file from the link you give it, imports it into your board, and then discards it. Section 3 explains exactly what is stored and for how long.

2. Uploading a file: data processed in your browser

  • Uploaded files — CSV and Excel files are parsed in your browser's memory. They are not uploaded to our servers or to any external service.
  • Board structure — Column names, types and groups are read from your monday.com board through the monday.com SDK to set up column mapping.
  • Board items — Existing items may be read to detect duplicates and to update matching rows.
  • Import usage counter — A count of imports this month, used for plan limits. It is kept in monday.com's app storage for your account, with your browser's localStorage as a fallback. It contains only a number.

All monday.com API calls for these imports go directly between your browser and monday.com. We do not intercept, proxy or store them.

The board view also asks our backend how many scheduled imports your account has run this month, so the plan limit covers both kinds of import. That request carries monday.com's signed session token, which identifies your monday.com account and user. It contains no file or board data.

3. Scheduled imports from a link

This feature is used only if someone on your account connects Ripple Import to monday.com (monday.com's OAuth sign-in) and saves a schedule.

  • File contents — Our backend downloads the file over HTTPS from the link you provide, when you preview the link during setup and at each scheduled run. It parses the file in memory, writes the rows to your board through monday.com's API, and then discards it. File contents are never written to disk or to storage, and nothing from the file is kept after the request or run finishes.
  • What we store — The schedule's settings (board ID, the source link, an optional access header you enter for a protected link, the column mapping, the run times and time zone); a history of the last 60 runs (start and finish times, how many items were created, updated, skipped or failed, and a short error message if a run failed); a monthly count of scheduled runs; and the monday.com OAuth access token for your account. These are kept in monday code's encrypted secure storage. Access headers are never sent back to the browser.
  • Where — Our backend runs in monday code's US region. monday code is monday.com's app hosting platform; monday.com names Google Cloud as the cloud provider behind it in its sub-processor list.
  • Retention — File contents: none, as above. Schedule settings and run history: until you delete the schedule. Access token: until you ask us to remove it; monday.com also invalidates it when the App is uninstalled. On request we delete everything held for your account.
  • Logs — Our backend's operational logs record account, board and schedule IDs, run counts and error messages. They never contain file contents. monday code holds these logs.

4. Sub-processors and third parties

  • monday.com Ltd — hosting (monday code) and storage for scheduled imports. monday.com's own sub-processors apply, as listed on its sub-processor page. Uploaded-file imports use no sub-processor beyond monday.com itself, which you already use.
  • Google Fonts — The App's interface font (Instrument Sans) loads from fonts.googleapis.com and fonts.gstatic.com. Like any web request, this lets Google see your IP address and browser details. No file or board data is sent.

The App does not use any analytics, tracking, advertising or error-reporting services. No cookies are set by the App.

5. Roles

Your organisation decides what data goes into its files and boards, so it is the controller of that data. For uploaded-file imports we do not process it at all. For scheduled imports we process it on your behalf, only to perform the imports you set up.

6. Data security

Uploaded-file imports take place entirely within your browser and your monday.com account. For scheduled imports, every request to our backend is verified with monday.com's signed session token, sources must use HTTPS, links to private or internal network addresses are refused, and stored access headers and tokens are kept in encrypted storage.

7. Children's privacy

The App is designed for use within the monday.com platform, which is a business tool. We do not knowingly collect data from children under 16.

8. Changes to this policy

We may update this Privacy Policy from time to time. Any changes will be reflected on this page with an updated date. Continued use of the App after changes constitutes acceptance of the updated policy.
